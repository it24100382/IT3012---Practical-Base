### Part 2: Theoretical Evaluation & Lecture Mapping

#### Question 1: State Space vs. Search Tree
**(Remember) You built your search logic based on the environment coordinates. What is the fundamental difference between the "State Space" and the "Search Tree"?**

- **State Space:** The finite graph of all possible environment configurations and valid physical transitions between them. In this grid world, the State Space consists of the set of unique $(x, y)$ coordinate positions bounded by `grid_size` that are not obstacles.
- **Search Tree:** A tree structure constructed dynamically by the search algorithm where each node represents a *path* through the state space starting from the initial state.
- **Fundamental Difference:** Multiple nodes in the Search Tree can correspond to the exact same state in the State Space (due to loops or redundant paths). The state space graph is static and bounded, whereas an unconstrained search tree can be infinite.

#### Question 2: Graph Search and the `reached` Set
**(Understand) In Step 1.2, you were instructed to use a `reached` set. In graph search theory, what specific problem does this set solve, and what would happen to your DFS agent without it?**

- **Problem Solved:** The `reached` (visited) set converts **Tree Search** into **Graph Search**. It tracks all previously expanded or enqueued states to prevent redundant state expansion and cyclic loops.
- **Consequence for DFS without `reached`:** Without the `reached` set, Depth-First Search (DFS) will enter an infinite loop when exploring cyclic paths (e.g. stepping Up $\rightarrow$ Right $\rightarrow$ Down $\rightarrow$ Left $\rightarrow$ Up). DFS will continuously append redundant paths to its stack, blowing up execution time and causing stack overflow non-termination.

#### Question 3: BFS vs. DFS Path Comparison & Optimality
**(Analyze) Compare the visual paths generated by BFS and DFS in your simulation. Why is BFS guaranteed to be optimal in this specific grid, whereas DFS produces winding, suboptimal routes?**

- **BFS Optimality Guarantee:** In an unweighted grid where every step action carries an identical step cost ($c = 1$), path cost $g(n)$ is strictly equal to path depth $d$. Breadth-First Search expands nodes in strict non-decreasing order of depth level ($d = 0, 1, 2, \dots$). Thus, the first time BFS reaches the goal state, it is mathematically guaranteed to be the shallowest (shortest / cost-optimal) path.
- **DFS Suboptimality:** DFS expands the deepest unvisited node first. It commits to a single path branch until hitting a dead end before backtracking. As a result, DFS explores long, erratic, winding detours across the grid rather than shortest routes.

#### Question 4: Memory Bottlenecks on a 1000x1000 Grid
**(Evaluate) If we scaled `visual_grid_game.py` up to a massive 1000x1000 grid, BFS and UCS might crash before finding food. According to the time and space complexity formulas from the lecture, contrast the memory bottlenecks of BFS versus DFS.**

- **BFS Space Complexity ($\mathcal{O}(b^d)$ or $\mathcal{O}(V)$):**
  - BFS must store all frontier nodes at the current depth in memory. On a $1000 \times 1000$ grid ($1,000,000$ states), the frontier at high search depths can contain hundreds of thousands of active nodes simultaneously. This exponential memory growth leads to Out-Of-Memory (OOM) system crashes.
- **DFS Space Complexity ($\mathcal{O}(b \cdot m)$):**
  - DFS only needs to store nodes along the single active path branch currently being explored, plus unexpanded sibling nodes at each depth level. For a $1000 \times 1000$ grid, the maximum search depth $m$ is linear relative to grid dimensions ($\sim 2000$ steps). DFS consumes minimal memory ($\sim \mathcal{O}(m)$), making its memory footprint negligible compared to BFS.
